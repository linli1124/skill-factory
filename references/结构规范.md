# 任务 → Skill 结构规范（知夏实证泛化 · 2026-10-18）

## 什么时候值得沉淀成 skill

- ✅ 重复任务（同一件事干第 2 次就该有 skill）
- ✅ 有明确步骤/规则/踩坑累积的任务
- ✅ 产出可验收的任务（有"做好没做好"的判断标准）
- ❌ 一次性任务（干完就走，经验进 memory 就够）
- ❌ 纯查询（那是搜索，不是流程）

## 标准结构（按任务大小伸缩）

**最小可用（第 1 次沉淀）**：
```
skill/ ├── SKILL.md（路由+死线+三问） └── 开工卡.md（L0 一屏）
```

**标准版（踩过坑后）**：加 `references/`（错题集优先——血泪是复用的根）

**完整版（大任务，参考知夏）**：references/题型+leaves、scripts、eval、assets、schemas、README

## 各层职责（铁律：同一信息只在一层）

| 层 | 装什么 | 不装什么 |
|---|---|---|
| SKILL.md | 路由、死线、触发词 | 任何操作细节 |
| 开工卡 | 每次做的动作（骨架可抄） | 知识/数据/为什么 |
| references/错题集 | 翻车记录（现象→根因→对策） | 操作步骤 |
| references/leaves | 查了才用的细则数据 | 流程 |
| scripts/eval | 机械检查（防忘防错） | 需要判断的东西 |
| README | 给人的入口、维护地图 | AI 执行内容 |

## 三条设计原则（知夏实战打得）

1. **渐进披露**：SKILL.md（必加载）→开工卡（做时读）→references（卡住查）——每层一屏
2. **防内部打架**：新旧机制更替时，**旧表述必须删干净**（只留"已作废"声明）；用矛盾词表机械扫（eval/rules-audit 模式）
3. **文字→脚本的进化**：忘过一次的规矩，第二形态是焊进死线，第三形态是 eval 脚本——**最终形态是机械拦截**

## 沉淀判据（经验分流表）

| 经验 | 去哪 |
|---|---|
| 每次都忘的动作 | 开工卡 |
| 翻过的坑 | 错题集 |
| 查了才用的数据 | references/leaves |
| 跨项目通用 | 本 skill（元层）/ user memory |
| 只对本项目 | 工作区 memory |
| 一次性 | 不记 |

## 触发词设计（SKILL.md description）

句式：**"当用户〈做什么场景〉时使用。触发词：A、B、C"**——触发词要覆盖用户会说的原话（口语词全收），description ≤1024 字符。

## 实例

`~/.workbuddy/skills/zhixia-character/`——知夏角色运营 skill，全结构实战版（三分支+eval+schemas），本规范的来源。
